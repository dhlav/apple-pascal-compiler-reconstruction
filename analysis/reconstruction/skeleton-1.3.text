PROGRAM PASCALSYSTEM;

{ The host program's variables are the OPERATING SYSTEM's
  globals. Under (*$U-*) the outer block compiles at lex -1,
  which is the system's own data segment, so declaring here
  does not collide with the compiler's globals at lex 0 -- the
  two are different segments. It is also not optional: the
  compiler reaches lex -1 at ten distinct offsets, and every
  one of them is accounted for by UCSD II.0's GLOBALS.TEXT
  laid out from offset 1. See finding 63.

  Only what the compiler actually touches is declared, in the
  order and at the sizes that put those ten offsets where the
  binary has them. Everything II.0 declares after USERINFO is
  past the last offset the compiler reads.

  The parameter types have to be here too, because a parameter
  list cannot see the TYPE block of the procedure it heads.
  CODEARRAY and SYMBUFARRAY restate the compiler's own, bounded
  by the MAXCODE and MAXCURSOR below. }

VAR SYSCOM: ^ INTEGER;
    GFILES: ARRAY [0..5] OF FIBP;
    USERINFO: INFOREC;

{ The operating system enters segment 1 as USERPROGRAM(NIL,NIL)
  -- two words of parameters, which is Apple's PARAM SIZE 4.
  The compiler NEWs its own buffers into them: the binary takes
  the address of both (LAO 1, LAO 2), stores to one exactly
  once, and reads them 70 and 33 times. See finding 59.

  CODEP is declared FIRST and lands at global 2, SYMBUFP second
  and lands at global 1, because parameters are allocated in
  reverse (finding 61b). GENBYTE's `SLDO 2` for CODEP^ is what
  measures this, and the order it forces is UCSD II.0's own
  (compglbls.text:252-253). }

SEGMENT PROCEDURE PASCALCOMPILER(CODEP: CODEPTR;
                                 SYMBUFP: SYMBUFPTR);
