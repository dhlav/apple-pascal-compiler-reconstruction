{ SETUP -- the Apple Pascal hardware/terminal configuration utility,
  APPLE3:SETUP.CODE. Reconstructed from the 1.3 binary
  (`analysis/utilities/SETUP-1.3-APPLE3.pcode.txt`/`.pas.txt`) --
  byte-identical between 1.1 and 1.3, and no shipped source exists on any
  evidence disk for either release.

  A large file: 54 procedures across 12 codefile segments. This is a
  first, scoped session -- the skeleton, the trivial pieces, and the
  menu/init machinery that everything else hangs off of, **compiling
  clean under Apple's own SYSTEM.COMPILER, first full attempt**. Real
  bodies: the SETUP segment's own outer body (SETUP.1 in the disk
  catalog's own naming), SETUP2/3/4/5/6, and the whole INITS segment
  (with one deliberate simplification, see INITS5 below). SETUP7 through
  SETUP26 -- the actual value-editing screens the CHANGE menu drives --
  and TEACHSET's own ten tutorial procedures are placeholder stubs,
  declared with plausible signatures (only ever called with zero
  arguments from what this session wrote) purely to hold their procedure
  NUMBER's place in line, since UCSD assigns numbers by declaration
  order and the menu's own CASE dispatch calls SETUP8/SETUP12 by that
  number.

  Frame sizes checked against Apple's binary (finding 122): the outer
  body EXACT (`4/352`), SETUP2 EXACT (`4/82`), SETUP3 EXACT (`6/164`),
  every one of NUMBER2..NUMBER9 EXACT (`0/0`, all eight). SETUP4 is a
  known, documented miss (`4/82` here against Apple's `4/2` -- see its
  own comment below); SETUP5/SETUP6 are `4/0` against Apple's `0/0`, an
  undiagnosed small params gap on two zero-argument FUNCTIONs, not yet
  chased. INITS's own nine procedures compile and the whole segment
  runs correctly in shape, but have not yet been checked one by one
  against Apple's own per-procedure frame sizes -- the natural next
  step alongside SETUP7 onward and TEACHSET.

  What SETUP actually does, from what's real so far: builds a binary
  search tree of named fields over SYSTEM.MISCINFO (the 96-word/192-byte
  terminal-profile record this program writes -- DISKSET.md's own "not
  started" data file, and this is the way in to it, per docs/PLAN.md).
  Each field's name maps to an (OFS, BIT, BITS) triple describing where
  in that record its value lives; INITS builds the whole tree once at
  startup (INITS.8/INITS.9's own long call sequences, "HAS CLOCK" at
  word 29 bit 0, "SCREEN HEIGHT" at word 37, and so on) plus two small
  linked lists of named values (TRUE/FALSE, and two more groups for
  8/16-bit prefixed-key fields) a value gets looked up against when the
  user types a new one. The exact meaning of OFS/BIT/BITS as bit
  offsets into MISCINFO -- and MISCINFO's own field layout -- is not
  decoded further than "these are opaque integers this session's own
  code never interprets," since nothing written here needs to.

  Structure: this is not `(*$U-*) PROGRAM SETUP; ... BEGIN <menu loop>
  END.` the way a first reading of `lex=0` suggested -- that shape hit
  error 125 on `EXIT(PROGRAM)` and error 104 on `EXIT(SETUP)`.
  `SYSTEM.COMPILER`'s own skeleton
  (`analysis/reconstruction/skeleton-1.3.text`) settles what the real
  shape is: `(*$U-*) PROGRAM PASCALSYSTEM;` wraps a
  `SEGMENT PROCEDURE PASCALCOMPILER(CODEP, SYMBUFP)`, and it is that
  inner segment procedure's own `EXIT(PASCALCOMPILER)` inside `BLOCK`,
  not the outer program, that the compiler's own `params=4` (the OS's
  `(NIL,NIL)` two-word invocation convention, the same "hidden bootstrap
  params" `BINDER.text`'s own outer body already carries) shows up on.
  Ported the identical shape here: `PROGRAM PASCALSYSTEM` outermost,
  trivial `BEGIN END.`; `SEGMENT PROCEDURE SETUP(P1, P2: ANYPTR)` one
  level in, taking the same two unused words, holding everything below
  and the real menu-loop body; `EXIT(SETUP)` inside `SETUP2` now
  resolves the same way `EXIT(PASCALCOMPILER)` does.

  PASCALSY's own real content here (`XIT` plus one leftover byte)
  against `SYSTEM.COMPILER`'s empty/absent one (finding 105a/119) is an
  open parallel, not settled evidence either way -- both outer bodies
  are the same trivial `BEGIN END.` shape, so whatever makes one produce
  a real dictionary entry and the other nothing is still unexplained. }
(*$I-*)
(*$U-*)
PROGRAM PASCALSYSTEM;

  TYPE
    ANYPTR = ^INTEGER;

SEGMENT PROCEDURE SETUP(P1, P2: ANYPTR);
{ P1/P2: the OS's own (NIL, NIL) two-word invocation convention every
  segment-1 program gets (SYSTEM.COMPILER's own skeleton, finding 59) --
  never read here, matching PASCALCOMPILER's own CODEP/SYMBUFP being the
  only two params that convention ever needs to carry meaning. }

  TYPE
    { A named-value list entry -- 43 words per NEW(x,43). Two lists of
      these exist (WIDENAMES/KEYNAMES, built by INITS.9) besides the boolean
      one (BOOLNAMES, built by INITS.8); each is a plain linked list,
      newest entry first (INITS.7's own I1,1 := L44 at the end).
      Declared before FIELDNODE below since FIELDNODE.VALUES needs the
      type name already in scope. }
    VALPTR = ^VALNODE;
    VALNODE = RECORD
                NEXT: VALPTR;
                TAG:  INTEGER;
                NAME: STRING
              END;
    { The field tree's own node -- 47 words per NEW(x,47) at every
      creation site (INITS.4 for the sentinel/root, INITS.6 for every
      real field). OFS/BIT/BITS are read verbatim off the two integer
      arguments and the enclosing (shared, lexically-scoped) BITS/VALUES
      context INITS.6 is called under; LEFT/RIGHT are BST children,
      both pointing at the shared SENTINEL node when empty rather than
      NIL -- the classic sentinel trick SETUP3's own search loop relies
      on to terminate without a separate NIL check. }
    NODEPTR = ^FIELDNODE;
    FIELDNODE = RECORD
                  OFS:    INTEGER;   {   0 }
                  BIT:    INTEGER;   {   1 }
                  BITS:   INTEGER;   {   2 }
                  VALUES: VALPTR;    {   3 }
                  LEFT:   NODEPTR;   {   4 }
                  RIGHT:  NODEPTR;   {   5 }
                  NAME:   STRING     {   6, 41 words }
                END;
    { SYSTEM.MISCINFO's own on-disk shape -- 96 words, matching
      DISKSET.md's own 192-byte listing. Each word is a variant --
      overlaid as a whole INTEGER for block I/O and as sixteen
      individual bits for SETUP17/SETUP18's own pack/unpack -- the
      same idiom already established and compiled clean in
      SET40COLS.text's own FLAGBYTE. `0..1`, not BOOLEAN: SETUP17's
      own pack does direct arithmetic on a bit value
      (`RESULT+RESULT+bit`), which BOOLEAN can't do without an
      explicit test. }
    MISCWORD = PACKED RECORD CASE INTEGER OF
                 0: (ASINT: INTEGER);
                 1: (BIT: PACKED ARRAY [0..15] OF 0..1)
               END;
    MISCREC = ARRAY [0..95] OF MISCWORD;

  VAR
    ROOT:      NODEPTR;    { G9, the field tree's own root }
    SENTINEL:  NODEPTR;    { G8, the shared sentinel every empty child
                             points to instead of NIL }
    CUR, PARENT: NODEPTR;  { G7, G6 -- SETUP3's own search cursor and
                             the parent it last stepped from }
    BOOLNAMES: VALPTR;     { G12, 'T'/'TRUE' and 'F'/'FALSE' }
    WIDENAMES: VALPTR;     { G11, built under BITS=16 (SCREEN
                             HEIGHT/WIDTH) }
    KEYNAMES: VALPTR;     { G10, built under BITS=8 (the LEAD-IN /
                             cursor-movement / key-binding group) }
    ALLOCQUANTUM: INTEGER; { G14, one NEW(x,1)'s own heap-block size in
                             words, measured once via two MARK snapshots
                             -- INITS5's own now-stubbed heap-trim uses
                             it as a scale factor }
    LASTKEY:  CHAR;        { G3, SETUP5's own last-read, case-folded key }
    DOTCOL:   INTEGER;     { G13, the "INITIALIZING...." progress dot's
                             own column, wrapping at 40 }
    QUITFLAG: BOOLEAN;     { G5, set true on '!' (SETUP5), read by
                             SETUP8's own QUIT-menu loop }
    G4:       INTEGER;     { set to 10 at the very end of INITS's own
                             top-level body; not otherwise touched by
                             anything this session wrote -- purpose not
                             yet known }
    MISCINFO: MISCREC; { G15 }
    CTRLNAMES: ARRAY [0..33] OF STRING[3]; { G111 -- 'NUL'..'SP', the 33
                             control-character names (INITS2/INITS3),
                             plus one scratch slot at index 33 reused by
                             SETUP10's own value-entry logic (not written
                             this session) }

  { SETUP2/SETUP3/SETUP4 (the bug-check, BST search, and trim
    utilities) are FORWARD-declared here, ahead of their real bodies
    further down, purely so INITS -- declared next, and needing all
    three -- can see them. This doesn't disturb their procedure
    NUMBERS: finding 61 established that declaration order (where a
    header is parsed, FORWARD or not) IS the numbering -- these three
    are declared FORWARD in the order 2, 3, 4 and completed in the
    same order 2, 3, 4 further down, so the numbers land right either
    way. (Finding 126 caught a later, wrong paraphrase of this same
    finding -- "numbers assign where a body is compiled, not where a
    FORWARD stub is" -- that this comment used to carry: a group of
    FORWARDs declared out of identifier order, needed for SETUP12, hit
    it directly.) Separately, no segment procedure may follow a body
    that's already been compiled without tripping error 399
    (CODEINSEG) -- which is what led to this ordering in the first
    place: NUMBER2's own declaration hit exactly that error, right
    after SETUP26's real body, until every SEGMENT PROCEDURE below was
    moved ahead of
    all 25 of SETUP2..26's own real bodies (finding: SETUP session,
    2026-08-28). }
  PROCEDURE SETUP2(LOC: STRING; OK: BOOLEAN);
    FORWARD;
  FUNCTION SETUP3(KEY: STRING): BOOLEAN;
    FORWARD;
  PROCEDURE SETUP4(VAR DEST: STRING; VAR SRC: STRING);
    FORWARD;

  SEGMENT PROCEDURE NUMBER2; BEGIN END;
  SEGMENT PROCEDURE NUMBER3; BEGIN END;
  SEGMENT PROCEDURE NUMBER4; BEGIN END;
  SEGMENT PROCEDURE NUMBER5; BEGIN END;
  SEGMENT PROCEDURE NUMBER6; BEGIN END;
  SEGMENT PROCEDURE NUMBER7; BEGIN END;
  SEGMENT PROCEDURE NUMBER8; BEGIN END;
  SEGMENT PROCEDURE NUMBER9; BEGIN END;

  { All of SETUP's own one-time startup work: builds the control-
    character name table, the field tree's sentinel/root pair, the
    three named-value lists, and the whole field tree itself (INITS8/
    INITS9's own long call sequences below), printing "INITIALIZING"
    with a progress dot per field as it goes. }
  SEGMENT PROCEDURE INITS;

    { Fills CTRLNAMES[0..32] with the 33 ASCII control-character names,
      NUL through SP, via the nested INITS3 below -- I1,1 in the
      original, the running index, is this procedure's own local. }
    PROCEDURE INITS2;
      VAR
        NEXTIDX: INTEGER;

      PROCEDURE INITS3(NAME: STRING);
      BEGIN
        NEXTIDX := NEXTIDX + 1;
        CTRLNAMES[NEXTIDX] := NAME
      END;

    BEGIN
      NEXTIDX := -1;
      INITS3('NUL'); INITS3('SOH'); INITS3('STX'); INITS3('ETX');
      INITS3('EOT'); INITS3('ENQ'); INITS3('ACK'); INITS3('BEL');
      INITS3('BS');  INITS3('HT');  INITS3('LF');  INITS3('VT');
      INITS3('FF');  INITS3('CR');  INITS3('SO');  INITS3('SI');
      INITS3('DLE'); INITS3('DC1'); INITS3('DC2'); INITS3('DC3');
      INITS3('DC4'); INITS3('NAK'); INITS3('SYN'); INITS3('ETB');
      INITS3('CAN'); INITS3('EM');  INITS3('SUB'); INITS3('ESC');
      INITS3('FS');  INITS3('GS');  INITS3('RS');  INITS3('US');
      INITS3('SP')
    END;

    { Trims the heap block a just-copied name string consumed back down
      to only what its actual length needs -- MARK/RELEASE pointer
      arithmetic scaled by ALLOCQUANTUM in the binary's own version.
      Not reproduced: a no-op here, so every name this session's own
      code allocates keeps its full worst-case buffer instead. Harmless
      for compiling and running (just more heap used, not less), and
      documented rather than guessed at (*STUB*). }
    PROCEDURE INITS5(VAR S: STRING);
    BEGIN
    END;

    { Builds the field tree's sentinel/root pair and the three named-
      value lists; CURVALUES/CURBITS are the shared context INITS6's
      own new nodes are built under -- set by INITS8/INITS9 before each
      run of INITS6 calls, read here only to pass into NEW's own field
      assignment below. }
    PROCEDURE INITS4;
      VAR
        CURVALUES: VALPTR;
        CURBITS:   INTEGER;

      { One named-value list entry, prepended to the shared list
        CURVALUES points at (INITS8/INITS9 each rebind CURVALUES before
        their own run of these). }
      PROCEDURE INITS7(TAG: INTEGER; NAME: STRING);
        VAR
          NEWNODE: VALPTR;
      BEGIN
        NEW(NEWNODE);
        NEWNODE^.NEXT := CURVALUES;
        NEWNODE^.TAG := TAG;
        NEWNODE^.NAME := NAME;
        INITS5(NEWNODE^.NAME);
        CURVALUES := NEWNODE
      END;

      { One field: NAME (trimmed and BST-inserted), at (OFS, BIT) under
        the shared (CURVALUES, CURBITS) context. Prints one progress
        dot, wrapping the line at 40. The `SETUP2(NOT SETUP3(...))`
        call is a duplicate-name assertion, not a real find -- inserting
        a brand new field must NOT already be in the tree. }
      PROCEDURE INITS6(NAME: STRING; OFS, BIT: INTEGER);
        VAR
          TRIMMED: STRING;
          NEWNODE: NODEPTR;
      BEGIN
        WRITE(CHR(46));
        DOTCOL := DOTCOL + 1;
        IF DOTCOL = 40 THEN
        BEGIN
          WRITELN;
          DOTCOL := 0
        END;
        SETUP4(TRIMMED, NAME);
        SETUP2(CONCAT('ENTER ', NAME), NOT SETUP3(TRIMMED));
        NEW(NEWNODE);
        NEWNODE^.NAME := NAME;
        INITS5(NEWNODE^.NAME);
        NEWNODE^.OFS := OFS;
        NEWNODE^.BIT := BIT;
        NEWNODE^.BITS := CURBITS;
        NEWNODE^.VALUES := CURVALUES;
        NEWNODE^.LEFT := SENTINEL;
        NEWNODE^.RIGHT := SENTINEL;
        SETUP4(TRIMMED, PARENT^.NAME);
        IF TRIMMED > NAME THEN
        BEGIN
          PARENT^.RIGHT := NEWNODE
        END
        ELSE
        BEGIN
          PARENT^.LEFT := NEWNODE
        END
      END;

      { The boolean-valued fields -- HAS CLOCK through STUDENT (offset
        29, one bit each), then the eight PREFIXED[...] terminal-
        capability flags (offset 36). }
      PROCEDURE INITS8;
      BEGIN
        CURVALUES := BOOLNAMES;
        INITS7(1, 'T'); INITS7(0, 'F');
        INITS7(1, 'TRUE'); INITS7(0, 'FALSE');
        CURBITS := 1;
        INITS6('HAS CLOCK', 29, 0);
        INITS6('HAS 8510A', 29, 1);
        INITS6('HAS LOWER CASE', 29, 2);
        INITS6('HAS RANDOM CURSOR ADDRESSING', 29, 3);

        INITS6('STUDENT', 29, 5);
        INITS6('PREFIXED[MOVE CURSOR UP]', 36, 0);
        INITS6('PREFIXED[MOVE CURSOR RIGHT]', 36, 1);
        INITS6('PREFIXED[ERASE TO END OF LINE]', 36, 2);
        INITS6('PREFIXED[ERASE TO END OF SCREEN]', 36, 3);
        INITS6('PREFIXED[MOVE CURSOR HOME]', 36, 4);
        INITS6('PREFIXED[DELETE CHARACTER]', 36, 5);
        INITS6('PREFIXED[ERASE SCREEN]', 36, 6);
        INITS6('PREFIXED[ERASE LINE]', 36, 7);
        INITS6('PREFIXED[KEY FOR MOVING CURSOR RIGHT]', 47, 0);
        INITS6('PREFIXED[KEY FOR MOVING CURSOR LEFT]', 47, 1);
        INITS6('PREFIXED[KEY FOR MOVING CURSOR UP]', 47, 2);
        INITS6('PREFIXED[KEY FOR MOVING CURSOR DOWN]', 47, 3);
        INITS6('PREFIXED[NON-PRINTING CHARACTER]', 47, 4);
        INITS6('PREFIXED[KEY FOR STOP]', 47, 6);
        INITS6('PREFIXED[KEY FOR BREAK]', 47, 7);
        INITS6('PREFIXED[KEY FOR FLUSH]', 47, 8);
        INITS6('PREFIXED[KEY TO END FILE]', 47, 9);
        INITS6('PREFIXED[EDITOR ''ESCAPE'' KEY]', 47, 10);
        INITS6('PREFIXED[KEY TO DELETE LINE]', 47, 11);
        INITS6('PREFIXED[KEY TO DELETE CHARACTER]', 47, 12);
        INITS6('PREFIXED[EDITOR "ACCEPT" KEY]', 47, 13)
      END;

      { The numeric/key-binding fields, in two BITS-width groups. }
      PROCEDURE INITS9;
      BEGIN
        CURBITS := 16;
        CURVALUES := WIDENAMES;
        INITS6('SCREEN HEIGHT', 37, 0);
        INITS6('SCREEN WIDTH', 38, 0);
        CURBITS := 8;
        CURVALUES := KEYNAMES;
        INITS6('LEAD-IN TO SCREEN', 31, 0);
        INITS6('MOVE CURSOR HOME', 31, 8);
        INITS6('ERASE TO END OF SCREEN', 32, 0);
        INITS6('ERASE TO END OF LINE', 32, 8);
        INITS6('MOVE CURSOR RIGHT', 33, 0);
        INITS6('MOVE CURSOR UP', 33, 8);
        INITS6('BACKSPACE', 34, 0);
        INITS6('ERASE LINE', 35, 0);
        INITS6('ERASE SCREEN', 35, 8);
        INITS6('KEY TO MOVE CURSOR UP', 39, 0);
        INITS6('KEY TO MOVE CURSOR DOWN', 39, 8);
        INITS6('KEY TO MOVE CURSOR LEFT', 40, 0);
        INITS6('KEY TO MOVE CURSOR RIGHT', 40, 8);
        INITS6('KEY TO END FILE', 41, 0);
        INITS6('KEY FOR FLUSH', 41, 8);
        INITS6('KEY FOR BREAK', 42, 0);
        INITS6('KEY FOR STOP', 42, 8);

        INITS6('KEY TO DELETE LINE', 44, 0);
        INITS6('EDITOR "ESCAPE" KEY', 44, 8);

      END;

    BEGIN
      NEW(ROOT);
      ROOT^.NAME := '';
      NEW(ROOT^.LEFT);
      SENTINEL := ROOT^.LEFT;
      NEW(BOOLNAMES);
      NEW(WIDENAMES);
      INITS5(WIDENAMES^.NAME);
      NEW(KEYNAMES);
      INITS5(KEYNAMES^.NAME);
      INITS8;
      INITS9
    END;

  BEGIN
    SETUP2('INITS', 16 = 15 + 1);
    { ALLOCQUANTUM itself -- the size, in words, of one NEW(x,1) heap
      block, measured in the binary via two consecutive heap marks --
      is never set here, matching INITS5's own stubbed no-op: nothing
      this session wrote reads it either. }
    QUITFLAG := FALSE;
    INITS2;
    WRITE('INITIALIZING');
    DOTCOL := 12;
    INITS4;
    WRITELN;

  { The tutorial screens (T(EACH) on the main menu) -- ten procedures,
    not written this session. }
  SEGMENT PROCEDURE TEACHSET; BEGIN END;

  { Bug-check: if OK is false, print the standard "BUG LOCATION" notice
    (matching this session's own BINDER.text CHECKERR almost verbatim)
    naming LOC, and terminate the whole program. Every call site this
    session wrote passes a literally-constant TRUE expression
    (`16 = 15 + 1`) -- Apple's own compiler folds it away, so it reads
    as a deliberate, always-true sanity assertion rather than dead code;
    kept as-is rather than simplified to `TRUE`, since a real developer
    assertion (comparing two named constants that happen to both equal
    16) is a more plausible original than a literal `TRUE` would be. }
  PROCEDURE SETUP2(*LOC: STRING; OK: BOOLEAN*);
  BEGIN
    IF NOT OK THEN
    BEGIN
      WRITE('BUG LOCATION ');
      WRITE(LOC);
      WRITELN;
      WRITE('PLEASE WRITE DOWN THIS LOCATION AND ANY');
      WRITELN;
      WRITE('SUPPORTING DETAILS YOU CAN, AND REPORT');
      WRITELN;
      WRITE('IT TO THE UCSD SUPPORT STAFF AT YOUR');
      WRITELN;
      WRITE('EARLIEST CONVENIENCE');
      WRITELN;
      EXIT(SETUP)
    END
  END;

  { BST search for KEY, using the SENTINEL trick: KEY is copied into the
    sentinel's own name first, so the loop is guaranteed to terminate
    (worst case, at the sentinel itself) without a separate NIL check.
    Descends via SETUP4's own trimmed comparison at each step, leaving
    CUR at the matching node (or the sentinel, if not found) and PARENT
    at whatever CUR was one step before -- both read afterward by
    whatever called this (not written this session). }
  FUNCTION SETUP3(*KEY: STRING): BOOLEAN*);
    VAR
      TRIMMED: STRING;
  BEGIN
    SENTINEL^.NAME := KEY;
    CUR := ROOT;
    TRIMMED := '';
    WHILE TRIMMED <> KEY DO
    BEGIN
      PARENT := CUR;
      IF TRIMMED > KEY THEN
      BEGIN
        CUR := CUR^.RIGHT
      END
      ELSE
      BEGIN
        CUR := CUR^.LEFT
      END;
      SETUP4(TRIMMED, CUR^.NAME)
    END;
    SETUP3 := CUR <> SENTINEL
  END;

  { DEST := SRC with trailing blanks trimmed. First written with SRC as a
    value STRING parameter, matching observable behavior but costing a
    real, large miss: `params=4/data=82` against Apple's `4/2`. The
    binary's own procedure 4 pushes SRC's address for both the `SAS` that
    does `DEST := SRC` and the later `LDB`/`STB` byte reads -- i.e. SRC is
    `VAR`, not value, which is what actually explains the whole gap: a
    value STRING parameter costs the usual ~41-word hidden copy-on-entry
    seen elsewhere in this project (`CHECKERR`, `SETUP2`), and `VAR`
    never pays it. Every call site passes an lvalue (`CUR^.NAME`,
    `PARENT^.NAME`, or INITS6's own value parameter `NAME`), so `VAR`
    costs nothing at any call site. The binary's own SCAN/MOVELEFT
    instruction shape is not reproduced here -- this keeps the
    DELETE-loop but fixes the parameter passing, which is what the frame
    size actually depends on. }
  PROCEDURE SETUP4(*VAR DEST: STRING; VAR SRC: STRING*);
  BEGIN
    DEST := SRC;
    WHILE (LENGTH(DEST) > 0) AND (DEST[LENGTH(DEST)] = ' ') DO
    BEGIN
      DELETE(DEST, LENGTH(DEST), 1)
    END
  END;

  { Read one command key: FEOLN (an empty line, just RETURN) reads as
    CHR(13); a lowercase letter is folded to uppercase; '!' sets
    QUITFLAG (SETUP8's own QUIT-loop reads it as "leave now, no more
    prompts"). }
  FUNCTION SETUP5: CHAR;
  BEGIN
    READ(LASTKEY);
    IF EOLN THEN
    BEGIN
      LASTKEY := CHR(13)
    END
    ELSE
    BEGIN
      IF LASTKEY IN ['a'..'z'] THEN
      BEGIN
        LASTKEY := CHR(ORD(LASTKEY) - 32)
      END
    END;
    IF LASTKEY = '!' THEN
    BEGIN
      QUITFLAG := TRUE
    END;
    SETUP5 := LASTKEY
  END;

  { A yes/no prompt, re-asked until answered. }
  FUNCTION SETUP6: BOOLEAN;
  BEGIN
    REPEAT
      WRITE('              C(ONTINUE)  Q(UIT)');
      WRITELN
    UNTIL SETUP5 IN ['C', 'Q'];
    SETUP6 := LASTKEY = 'C'
  END;

  { SETUP8 through SETUP26 -- the QUIT handler and the whole CHANGE
    submenu -- are not written this session except SETUP7, which is
    self-contained (only calls SETUP4/SETUP5, both earlier) and
    genuinely is a lex-1 sibling of SETUP1-11 in Apple's own binary.
    SETUP12 is also lex 1, but SETUP13 through SETUP26 are lex 2-4 in
    the lift (`analysis/utilities/SETUP-1.3-APPLE3.pas.txt`) -- they
    are procedures nested INSIDE SETUP12's own declaration part, not
    flat top-level siblings the way 7-11 are. A first attempt wrote
    12-26 as flat stubs/bodies with SETUP14/15/25/26 FORWARD-declared
    ahead of SETUP12 to let it call them; that compiled clean but with
    every procedure NUMBER wrong from 7 onward once diffed against
    Apple's own binary, because a FORWARD reserves the next sequential
    number immediately, at declaration -- exactly what finding 61
    itself says ("declaration order is the numbering"), but not what
    this file's own SETUP2/3/4 comment above used to paraphrase it as
    ("assigns where a body is compiled, not where a FORWARD stub is").
    That paraphrase happened to give the right answer for SETUP2/3/4
    only because those three are declared FORWARD and completed in the
    same relative order (2, 3, 4 both times); a group of forwards
    declared out of identifier order is what exposed it as wrong
    (finding 126). Nesting SETUP13-26 inside SETUP12 properly is the
    real fix, not attempted yet -- the natural next session. }

  { Read one edited line into L3: '/' backspaces, echoing a `<` the
    first time in a run of them; '<' zaps the whole buffer; RETURN or
    '!' ends entry. Trims embedded spaces via SETUP4 before returning
    -- FALSE means an empty or '!'-aborted answer. }
  FUNCTION SETUP7(VAR L3: STRING): BOOLEAN;
    VAR
      ECHOING: BOOLEAN;
  BEGIN
    SETUP7 := TRUE;
    ECHOING := FALSE;
    L3 := '';
    WHILE NOT (SETUP5 IN [CHR(13), '!']) DO
    BEGIN
      IF (LASTKEY <> '/') AND ECHOING THEN
      BEGIN
        ECHOING := FALSE;
        WRITE('>')
      END;
      IF LASTKEY = '<' THEN
      BEGIN
        L3 := '';
        WRITE('<<ZAP>>');
        WRITELN
      END
      ELSE IF LASTKEY = '/' THEN
      BEGIN
        IF LENGTH(L3) > 0 THEN
        BEGIN
          IF NOT ECHOING THEN
          BEGIN
            WRITE('<')
          END;
          ECHOING := TRUE;
          IF L3[LENGTH(L3)] IN [' '..'~'] THEN
          BEGIN
            WRITE(L3[LENGTH(L3)])
          END
          ELSE
          BEGIN
            WRITE('?')
          END;
          DELETE(L3, LENGTH(L3), 1)
        END
      END
      ELSE
      BEGIN
        IF LASTKEY IN [' '..'~'] THEN
        BEGIN
          WRITE(LASTKEY)
        END
        ELSE
        BEGIN
          WRITE('?')
        END;
        L3 := CONCAT(L3, ' ');
        L3[LENGTH(L3)] := LASTKEY
      END
    END;
    IF LASTKEY = '!' THEN
    BEGIN
      SETUP7 := FALSE
    END;
    WRITELN;
    SETUP4(L3, L3);
    IF LENGTH(L3) = 0 THEN
    BEGIN
      SETUP7 := FALSE
    END
  END;

  PROCEDURE SETUP8; BEGIN END;
  { Displays VALUE in octal, decimal, and hexadecimal -- and, when
    SHOWCHAR, its ASCII/CONTROL name too -- the read-out line the
    numeric and scalar editors both print before prompting for a new
    value. The octal/hex digit columns are a variant-record view of
    VALUE itself (matching SETUP17/18's own bit-view idiom), packed
    5-per-word/3-bit for octal and 4-per-word/4-bit for hex; a
    negative value's own octal top "digit" is only one bit wide, so
    it prints as a literal leading 1 rather than going through the
    general digit loop. }
  PROCEDURE SETUP9(SHOWCHAR: BOOLEAN; VALUE: INTEGER);
    TYPE
      OCTVIEW = PACKED RECORD CASE INTEGER OF
                  0: (ASINT: INTEGER);
                  1: (DIGIT: PACKED ARRAY [0..4] OF 0..7)
                END;
      HEXVIEW = PACKED RECORD CASE INTEGER OF
                  0: (ASINT: INTEGER);
                  1: (DIGIT: PACKED ARRAY [0..3] OF 0..15)
                END;
    VAR
      OCT: OCTVIEW;
      HEX: HEXVIEW;
      L6, I: INTEGER;
  BEGIN
    L6 := VALUE;
    OCT.ASINT := VALUE;
    HEX.ASINT := VALUE;
    WRITE(' OCTAL DECIMAL HEXADECIMAL');
    IF SHOWCHAR THEN
    BEGIN
      IF VALUE < 128 THEN
      BEGIN
        WRITE(' ASCII')
      END;
      IF VALUE < 32 THEN
      BEGIN
        WRITE(' CONTROL')
      END
    END;
    WRITELN;
    I := 4;
    IF VALUE < 0 THEN
    BEGIN
      WRITE('1')
    END
    ELSE
    BEGIN
      WRITE(' ');
      WHILE (OCT.DIGIT[I] = 0) AND (I > 0) DO
      BEGIN
        I := I - 1;
        WRITE(' ')
      END
    END;
    WHILE I >= 0 DO
    BEGIN
      WRITE(OCT.DIGIT[I]);
      I := I - 1
    END;
    WRITE(' ');
    WRITE(L6:6);
    WRITE('  ');
    I := 3;
    WHILE (HEX.DIGIT[I] = 0) AND (I > 0) DO
    BEGIN
      I := I - 1;
      WRITE(' ')
    END;
    WHILE I >= 0 DO
    BEGIN
      IF HEX.DIGIT[I] < 10 THEN
      BEGIN
        WRITE(HEX.DIGIT[I])
      END
      ELSE
      BEGIN
        WRITE(CHR(HEX.DIGIT[I] - 10 + 65))
      END;
      I := I - 1
    END;
    WRITE(' ':8);
    IF SHOWCHAR THEN
    BEGIN
      IF VALUE < 33 THEN
      BEGIN
        WRITE(CTRLNAMES[VALUE]);
        WRITE(' ':7 - LENGTH(CTRLNAMES[VALUE]))
      END
      ELSE IF VALUE = 127 THEN
      BEGIN
        WRITE('DEL');
        WRITE(' ':4)
      END
      ELSE IF VALUE IN [33..125] THEN
      BEGIN
        WRITE(CHR(VALUE));
        WRITE(' ':6)
      END;
      IF VALUE < 32 THEN
      BEGIN
        WRITE('^');
        WRITE(CHR(VALUE + 64))
      END
    END;
    WRITELN
  END;

  { SETUP12 -- the CHANGE submenu -- turns out to enclose ALL of
    SETUP13 through SETUP26 as nested procedures, not flat siblings
    (finding 126, from the lift's own lex levels: SETUP12 is lex 1,
    same as SETUP1-11, but 13-26 are lex 2-4). The nesting below
    mirrors the lex levels and the real call graph exactly, so nothing
    here needs a FORWARD declaration at all: every callee is declared
    (as a sibling earlier in the same enclosing scope, or as a child
    of the caller itself) before the point that calls it.

      SETUP12 (lex 1)
        SETUP13 (lex 2) -- real: a yes/no/quit prompt
        SETUP14 (lex 2) -- real: the radix submenu
          SETUP15 (lex 3) -- real: announces the current radix
        SETUP16 (lex 2) -- stub: the single-field dispatcher
          SETUP17 (lex 3) -- stub: bit-field pack
          SETUP18 (lex 3) -- stub: bit-field unpack
          SETUP19 (lex 3) -- stub: numeric entry driver
            SETUP20 (lex 4) -- stub: 2^n for bit-width
          SETUP21 (lex 3) -- stub: scalar-name entry driver
            SETUP22 (lex 4) -- stub: show current scalar value
            SETUP23 (lex 4) -- stub: list allowed scalar values
            SETUP24 (lex 4) -- stub: scalar name lookup
        SETUP25 (lex 2) -- real: S(ingle, look up one field by name
        SETUP26 (lex 2) -- real: P(rompted, in-order tree walk

    SETUP16 and everything nested inside it (17-24) are still empty
    stubs -- the actual numeric/scalar value-editing engine, not
    written this session. Their signatures are left bare for now
    rather than guessed; SETUP17-24 all reference their enclosing
    procedures' own parameters via lexical scoping in the real binary
    (e.g. SETUP17's `I1,1` is a level-1-up reference, reading SETUP16's
    own NODEPTR parameter, not a parameter of its own) rather than
    taking everything as explicit arguments, so their real signatures
    need that worked out together with their bodies, not guessed
    ahead of time. }
  PROCEDURE SETUP12;

    PROCEDURE SETUP16(L1: NODEPTR);
      { Packs the current field's own bits out of MISCINFO into
        RESULT (VAR), most-significant bit first. FIELD is a local
        copy of L1 (SETUP16's own parameter) -- OFS names the
        MISCINFO word, BIT/BITS the range within it. }
      PROCEDURE SETUP17(VAR RESULT: INTEGER);
        VAR
          LO, HI: INTEGER;
          FIELD: NODEPTR;
      BEGIN
        RESULT := 0;
        FIELD := L1;
        HI := FIELD^.BIT + FIELD^.BITS - 1;
        LO := FIELD^.BIT;
        WHILE HI >= LO DO
        BEGIN
          RESULT := RESULT + RESULT + MISCINFO[FIELD^.OFS].BIT[HI];
          HI := HI - 1
        END
      END;

      { The inverse of SETUP17: unpacks VALUE's own bits back into
        MISCINFO, least-significant bit first starting at BIT. A
        negative VALUE sets the field's own top bit (BIT+BITS-1) as a
        sign flag and continues with the magnitude. }
      PROCEDURE SETUP18(VALUE: INTEGER);
        VAR
          LO, HI: INTEGER;
          FIELD: NODEPTR;
      BEGIN
        FIELD := L1;
        IF VALUE < 0 THEN
        BEGIN
          MISCINFO[FIELD^.OFS].BIT[FIELD^.BIT + FIELD^.BITS - 1] := 1;
          VALUE := -VALUE
        END;
        LO := FIELD^.BIT;
        HI := FIELD^.BIT + FIELD^.BITS - 1;
        WHILE LO <= HI DO
        BEGIN
          MISCINFO[FIELD^.OFS].BIT[LO] := VALUE MOD 2;
          VALUE := VALUE DIV 2;
          LO := LO + 1
        END
      END;

      PROCEDURE SETUP19;

        { 2^N, via repeated doubling (the field's own bit WIDTH, used
          as the exclusive upper bound for an unsigned field's octal/
          decimal/hex entry range). }
        FUNCTION SETUP20(N: INTEGER): INTEGER;
          VAR
            ANSWER, I: INTEGER;
        BEGIN
          ANSWER := 1;
          FOR I := 1 TO N DO
          BEGIN
            ANSWER := ANSWER * 2
          END;
          SETUP20 := ANSWER
        END;

      PROCEDURE SETUP21;

        { Announces the field's current value by name: walks the
          value list (always BOOLNAMES for a scalar field -- SETUP16
          only reaches SETUP21 when the field's VALUES list is
          neither KEYNAMES nor WIDENAMES) until VALUE's own TAG
          matches, using SETUP2's bug-check with the list's own head
          as sentinel the same way SETUP3's BST search uses SENTINEL. }
        PROCEDURE SETUP22(VALUE: INTEGER);
          VAR
            P: VALPTR;
        BEGIN
          P := L1^.VALUES;
          SETUP2('SHOWSCALAR', P <> BOOLNAMES);
          WHILE VALUE <> P^.TAG DO
          BEGIN
            P := P^.NEXT;
            SETUP2('SHOWSCALAR', P <> BOOLNAMES)
          END;
          WRITE('CURRENT VALUE IS ');
          WRITE(P^.NAME);
          WRITELN
        END;

        { Lists every allowed value name for the field, walking the
          same circular value list once around. }
        PROCEDURE SETUP23;
          VAR
            P: VALPTR;
        BEGIN
          P := L1^.VALUES;
          WRITE('ALLOWED VALUES ARE:');
          WRITELN;
          REPEAT
            SETUP2('SHOWALL', P <> BOOLNAMES);
            WRITE(P^.NAME);
            WRITELN;
            P := P^.NEXT
          UNTIL P = BOOLNAMES
        END;

        { Looks NAME2 up in the value list by name (the SETUP3/SETUP24
          sentinel trick again: NAME2 is written into BOOLNAMES' own
          NAME field first, so the search is guaranteed to terminate
          at worst back at BOOLNAMES itself, with no separate bounds
          check). Sets VALUE to the matching TAG; FALSE means NAME2
          was not a real value name (the search wrapped all the way
          back to BOOLNAMES). }
        FUNCTION SETUP24(VAR VALUE: INTEGER; VAR NAME2: STRING): BOOLEAN;
          VAR
            P: VALPTR;
            TARGET: STRING;
        BEGIN
          TARGET := NAME2;
          P := L1^.VALUES;
          BOOLNAMES^.NAME := TARGET;
          WHILE P^.NAME <> TARGET DO
          BEGIN
            P := P^.NEXT
          END;
          VALUE := P^.TAG;
          SETUP24 := P <> BOOLNAMES
        END;

      BEGIN END;

    BEGIN END;
