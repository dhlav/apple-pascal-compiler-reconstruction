{ LIBMAP -- the Apple Pascal Library Map utility, APPLE2:LIBMAP.CODE.

  Reconstructed from the 1.3 binary. Eleven p-code procedures and one
  native routine -- and the native routine needs no new source at all: it
  is IDSEARCH, the compiler's own reserved-word lookup, linked in whole
  (finding 109). `PROCEDURE IDSEARCH(VAR IDREC, ID); EXTERNAL;` declared
  first, exactly as PASCALCO.text declares it, and SYSTEM.LINKER puts the
  same assembled procedure from src/native/SEARCH.TEXT in its place.

  Procedure numbers are fixed by declaration order and the binary fixes
  the order: IDSEARCH is 2, then 3 through 7 and 12 at the outer level,
  with 8 nested inside 7's own declaration part (lex 2), and 9, 10, 11
  nested inside 8 (lex 3) -- the lex levels in the p-code listing are the
  nesting, not a guess.

  The one segment dictionary LIBMAP reads is Apple's own on-disk format
  (block 0 of a library or codefile): addr/len per slot, then names, then
  segkind, then a table read but never named elsewhere in this file, then
  SEGINFO, seventy-two words this program never references at all, and a
  length-prefixed comment -- 256 words exactly, one disk block. Every
  field offset below is the LAO/LDO operand the binary uses, not a guess.

  Globals. SEGDICT is the whole dictionary block, INFILE the library being
  mapped, OUTFILE the map's destination. Four booleans and two integer
  tables (version strings, machine-type strings) follow, then two more
  integers the outer block's loop uses. Every name is ours; the offsets
  are Apple's.

  G603 was named DONEFLAG on no better evidence than "the fourth boolean
  after three that made sense" -- MAPLIBRARY's own body (proc 12) settles
  it: `IF NEEDSSWAP(SEGDICT) THEN BEGIN SWAPALL(SEGDICT); G603 := TRUE END`,
  read and unconditionally reset to FALSE at MAPLIBRARY's top. It is TRUE
  exactly when this library's dictionary needed correcting for the other
  machine's byte order, and SHOWONE reads it later to decide whether the
  reference stream it reads word-by-word off disk -- which SWAPALL never
  touches -- also needs swapping one entry at a time. Renamed SWAPPED. }

{ $I- : ordinary WRITE/WRITELN/RESET on OUTFILE and INFILE compile to the
  same CXP 0,n the binary calls directly (verified: WRITE(OUTFILE,S) and
  FWRITESTRING(@OUTFILE,S,0) are the same instructions). Without $I- every
  one of those calls carries an extra IOCHECK CSP the binary does not
  have.

  $G+ : Apple Pascal forbids GOTO unless this is set (language reference,
  p.1793) -- VALIDNAME's early exit needs it, and its absence here was a
  real bug this file carried since VALIDNAME was first written: the fast
  tier accepts GOTO regardless of any $G directive, so it never caught
  this, and only compiling against Apple's own SYSTEM.COMPILER did
  (finding: LIBMAP session, 2026-08-27).

  Does not need (*$U-*) or an OS FORWARD: GETWORD's block read is
  `BLOCKREAD`, a standard Pascal function (language reference,
  "Untyped File I/O Operations") the compiler recognizes by name the
  same way it recognizes WRITE, not a hand-declared reach into segment 0.
  A hand-declared `FUNCTION FBLOCKIO(...); FORWARD;` (segment 0
  procedure 28, the GLOBALS.TEXT idiom SYSTEM.PASCAL's own source uses
  internally) was
  tried first and genuinely does not work for an ordinary program even
  with $U-: error 160, "previous declaration was not forward", on the
  *next* declaration down (`IDSEARCH ... EXTERNAL`) once $U- was set,
  because $U-'s side effects (R-/G+/I-/V- all at once) change how the
  compiler treats EXTERNAL too, not just FORWARD. `BLOCKREAD` sidesteps
  the whole question -- it is what the fast tier's "guessing you meant
  blockread instead" diagnosis was pointing at all along (finding 111
  update, 2026-08-27). }
(*$I-*)
(*$G+*)
PROGRAM LIBMAP;

  TYPE
    DIRENTRY = RECORD
                 ADDR, LENG: INTEGER
               END;
    { Declared separately from SEGDICTREC.ADDRLEN's own inline array type
      so a VAR parameter of this type can bind to ADDRLEN directly --
      NEEDSSWAP's own real signature (finding 120). }
    ADDRLENARR = ARRAY [0..15] OF DIRENTRY;
    SEGNAMESTR = PACKED ARRAY [0..7] OF CHAR;
    SEGINFOREC = PACKED RECORD CASE INTEGER OF
                   0: (ASWORD: INTEGER);
                   1: (SEGNUM: 0..255; MTYPE: 0..15;
                       UNUSED: 0..1; VERSION: 0..7)
                 END;
    SEGDICTREC = RECORD
                   ADDRLEN:  ADDRLENARR;                     {   3 }
                   SEGNAME:  ARRAY [0..15] OF
                               PACKED ARRAY [1..8] OF CHAR;  {  35 }
                   SEGKIND:  ARRAY [0..15] OF INTEGER;       {  99 }
                   TEXTADR:  ARRAY [0..15] OF INTEGER;       { 115 }
                   SEGINFO:  ARRAY [0..15] OF SEGINFOREC;    { 131 }
                   SPARE:    ARRAY [1..72] OF INTEGER;       { 147, unread }
                   COMMENT:  STRING[79]                     { 219 }
                 END;
    { One 16-byte entry off a segment's own cross-reference stream, read by
      GETWORD and dispatched on by SHOWONE. RNAME is only meaningful for a
      handful of RKIND values (2,3,5,13,14,1,4 -- the ones SHOWREF prints);
      the last word (SPARE) is real disk space -- the entry is a fixed
      16-byte record -- but nothing in SHOWONE or GETWORD ever reads or
      writes it. }
    REFENTRY = PACKED RECORD
                 RNAME: SEGNAMESTR;
                 RKIND: 0..14;
                 RVAL1, RVAL2: INTEGER;
                 SPARE: INTEGER
               END;

  VAR
    SEGDICT:  SEGDICTREC;              {   3, one disk block }
    INFILE:   FILE;                    { 259, the library being mapped }
    OUTFILE:  TEXT;                    { 299, the map's destination }
    LISTMAP,                           { 600 }
    LISTREFS,                          { 601 }
    LISTLINK,                          { 602 }
    SWAPPED:  BOOLEAN;                 { 603, was DONEFLAG -- see above }
    VERSTRS:  ARRAY [0..7] OF STRING[7];    { 604, 'unknown'/'A2/1.n' }
    TYPESTRS: ARRAY [0..9] OF STRING[23];   { 636, machine-type names }
    TEMP2, TEMP1: INTEGER;             { 756, 757 }

  PROCEDURE IDSEARCH(VAR IDREC, ID);
    EXTERNAL;

  { Byte-swap a word in place -- read from a library the current machine
    did not write, whose words come the other way round (the type table
    at G636 spells out both: "P-Code (most sig. 1st)" and "(least sig.
    1st)"). Verified instruction for instruction against the binary,
    LDP/STP field offsets included. }
  PROCEDURE SWAPBYTES(VAR W: INTEGER);
    VAR
      OLDVAL, NEWVAL: PACKED RECORD CASE BOOLEAN OF
                        TRUE:  (ASWORD: INTEGER);
                        FALSE: (LO, HI: 0..255)
                      END;
  BEGIN
    OLDVAL.ASWORD := W;
    NEWVAL.HI := OLDVAL.LO;
    NEWVAL.LO := OLDVAL.HI;
    W := NEWVAL.ASWORD
  END;

  { TRUE if any of the sixteen words at P has a nonzero byte on the side
    a word's high byte would be if this machine mis-swapped it -- the
    test for "this library's dictionary was written on a machine with
    the other byte order". The endianness probe (set a word to 1, ask
    which byte holds it) is generic UCSD, not an Apple-specific trick;
    on the 6502 it always answers "byte 0". Not yet checked against the
    binary's own CHK placement on the constant index -- (*STUB*) in
    spirit, real in shape.

    WRONG PARAMETER TYPE, FIXED (finding 113 flagged this, MAPLIBRARY's
    own real call site -- finding 120 -- settles it): `VAR P: SEGWORDS`
    never survived contact with a real call. `LIBRARY.text`'s own copy of
    this same procedure hit the same wall first (error 142) and fixed it
    to `VAR P: ADDRLENARR` reading `P[I].ADDR`, verified exact there on
    both `params=6` and `data=10`; `MAPLIBRARY`'s own disassembly here
    calls it the identical way (`NEEDSSWAP(SEGDICT.ADDRLEN)`), so the same
    fix applies verbatim (finding 120). }
  FUNCTION NEEDSSWAP(VAR P: ADDRLENARR): BOOLEAN;
    TYPE
      WORDBYTES = PACKED RECORD CASE BOOLEAN OF
                    TRUE:  (ASWORD: INTEGER);
                    FALSE: (ASBYTES: PACKED ARRAY [0..1] OF 0..255)
                  END;
    VAR
      HIBYTE: 0..1;
      I, LAST: 0..15;
      W: WORDBYTES;
  BEGIN
    NEEDSSWAP := FALSE;
    W.ASWORD := 1;
    HIBYTE := ORD(W.ASBYTES[0] = 1);
    I := 0;
    LAST := 15;
    WHILE I <= LAST DO
    BEGIN
      W.ASWORD := P[I].ADDR;
      IF W.ASBYTES[HIBYTE] <> 0 THEN
      BEGIN
        NEEDSSWAP := TRUE
      END;
      I := I + 1
    END
  END;

  { Byte-swap every word in one dictionary block that came from a
    different-endian machine: both words of each ADDRLEN entry, then
    SEGKIND, TEXTADR and SEGINFO entry by entry. SEGKIND and SEGINFO go
    through a temporary and are written back; ADDRLEN and TEXTADR are
    swapped in place directly. Reconstructed from the shape of the
    binary's own loop; its own two extra words of locals (an address
    computed into its own temporary before SWAPBYTES dereferences it,
    same as NEEDSSWAP) are not yet accounted for here. }
  PROCEDURE SWAPALL(VAR D: SEGDICTREC);
    VAR
      I, LAST: 0..15;
      TEMP: INTEGER;
      INFOTEMP: SEGINFOREC;
  BEGIN
    I := 0;
    LAST := 15;
    WHILE I <= LAST DO
    BEGIN
      SWAPBYTES(D.ADDRLEN[I].ADDR);
      SWAPBYTES(D.ADDRLEN[I].LENG);
      TEMP := D.SEGKIND[I];
      SWAPBYTES(TEMP);
      D.SEGKIND[I] := TEMP;
      SWAPBYTES(D.TEXTADR[I]);
      INFOTEMP := D.SEGINFO[I];
      SWAPBYTES(INFOTEMP.ASWORD);
      D.SEGINFO[I] := INFOTEMP;
      I := I + 1
    END
  END;

  { TRUE iff all eight characters of a segment name are valid identifier
    characters (letter, digit, underscore or the blank padding) --
    checked before trusting a segment name at all. Verified instruction
    for instruction, including the early exit: the source leaves the
    result FALSE from the top and jumps straight past the loop rather
    than reassigning it. }
  FUNCTION VALIDNAME(VAR NAME: SEGNAMESTR): BOOLEAN;
    LABEL 1;
    VAR
      LAST, I: 0..7;
  BEGIN
    VALIDNAME := FALSE;
    I := 0;
    LAST := 7;
    WHILE I <= LAST DO
    BEGIN
      IF NOT (NAME[I] IN [' ', '0'..'9', 'A'..'Z', '_']) THEN
      BEGIN
        GOTO 1
      END;
      I := I + 1
    END;
    VALIDNAME := TRUE;
  1:
  END;

  { Walk all sixteen dictionary slots and print the ones actually in use
    (nonzero code address or length). Each gets a header -- SEGINFO's own
    segment number if it has one, the slot position if not (an older,
    pre-II.1 file has no SEGINFO at all) -- then the version/machine-type
    line or "Pre-II.1 segment", then SHOWONE's own detail, then a rule.

    The ADDRLEN test was originally written as a pointer
    (`ENTRY: ^DIRENTRY; ENTRY := @SEGDICT.ADDRLEN[SEGNUM]`), which the fast
    tier compiled without complaint. Apple's own compiler rejects `@`
    outright -- error 400, illegal character -- and `ADDR(x)` is simply an
    undeclared identifier; neither is real Apple Pascal 1.3 syntax, and
    nothing else in this whole reconstructed codebase uses either one.
    `WITH SEGDICT.ADDRLEN[SEGNUM] DO` produces the *identical* instruction
    sequence the binary has (`LAO`, index, bounds check, `IXA`, store into
    a hidden local -- confirmed against the fast tier instruction for
    instruction) with no pointer or address-of syntax at all: that address
    is WITH's own implementation, computed once and reused for both field
    reads, never exposed to the source (finding: LIBMAP session,
    2026-08-27). Reconstructed from the shape of the binary; not yet
    checked instruction for instruction beyond this one statement. }
  PROCEDURE SHOWSEGS;
    VAR
      SEGNUM, LASTSEG: 0..16;

    { Detail for one dictionary slot: a one-line header naming what kind
      of segment it is (SEGDICT.SEGKIND, 0..7, case-dispatched -- the
      part below this comment is verified against the disassembly
      instruction group by instruction group), the interface text for a
      library unit if there is one (SHOWINFO, (*STUB*) below), then --
      unless SHOWINFO already handled it and LISTLINK is off -- the
      segment's own cross-reference stream: one 16-byte entry per
      external reference, read entry-at-a-time from the block right
      after the segment's own code (ADDR + CEIL(LENG/512)), each entry
      an 8-char name printed 4-space-indented in a 12-column field, a
      kind (0..14, dispatched the same way as the header), and up to two
      more values whose meaning depends on the kind.

      The whole loop is now reconstructed and traced instruction for
      instruction against the binary (finding: LIBMAP session,
      2026-08-27), correcting two things the earlier (*STUB*) comment
      here got wrong: GETWORD does not read "a first word" -- it copies
      a whole 16-byte entry in one MOVELEFT, entry-indexed rather than
      byte-indexed -- and LISTREFS is not confined to SHOWREF's own body;
      it directly gates the "external proc" case (RKIND 9/10) here too,
      the same way LISTLINK gates RKIND 6/7/8.

      **Acceptance-tier verified**: compiles clean under Apple's own
      SYSTEM.COMPILER (no fast-tier substitute -- `xcompile.py`'s
      `moveleft`/`blockread` builtins take three and four arguments,
      not the five and six the real UCSD calls compile down to, so this
      procedure was never checkable there) and reproduces Apple's own
      `params=2/data=556` for SHOWONE and `params=2/data=2` for GETWORD
      exactly (LIBMAP session, 2026-08-27). GETWORD needed one more
      correction along the way: Apple's own frame has no local for the
      read-position index at all (`32 - BYTEPOS` is computed inline in
      the `MOVELEFT` call, not stored) -- an `IDX` local here gave
      `data=4`, two words over, until it was removed. }
    PROCEDURE SHOWONE(SEGNUM: INTEGER);
      VAR
        BYTEPOS:  0..32;               { local2: entries left unread in RBUF }
        RBLOCK:   INTEGER;             { local3: next block to read }
        ENTRY:    REFENTRY;            { locals 4-11, one entry off the stream }
        NEEDINFO: BOOLEAN;             { local13 -- local12 between ENTRY and
                                          here is real, unreferenced anywhere
                                          in this procedure, and unexplained }
        RBUF:     ARRAY [0..31] OF REFENTRY;  { local14: one disk block, 32
                                                 entries * 8 words = 256 words
                                                 = 512 bytes exactly }
        SWAPBUF:  ARRAY [0..7] OF INTEGER;    { local270, the swap scratch }
        I, LAST:  0..7;                       { local278, local279: swap-loop
                                                 counters. local279 is reused
                                                 earlier in this procedure (a
                                                 WITH-temp for the RBLOCK
                                                 computation below) -- normal
                                                 p-code offset reuse, not a
                                                 second declaration. }
        SPARE:    INTEGER;  { local280 -- closes params=2/data=556 exactly
                               against Apple's own compiler, confirmed this
                               session (LIBMAP session, 2026-08-27). Trying
                               it as a 276-element ARRAY OF INTEGER first
                               overshot to data=1106: this position costs
                               2 words per declared array element here, not
                               1 (confirmed empirically -- data dropped to
                               574 at 10 elements, 556 at exactly 1), a
                               real anomaly this file does not have an
                               explanation for yet. A bare scalar INTEGER
                               sidesteps the question and matches exactly.
                               Never read or written anywhere in this
                               procedure -- true identity unknown, same as
                               local12 above. }

      { TRUE if SHOWINFO gave a full account of this segment's own
        interface text, so SHOWONE should not also print the raw
        reference stream unless LISTLINK asked for it explicitly. Every
        call site (SHOWSEGS, already exact) passes just the one BLK
        argument; an earlier note here claiming two extra zero arguments
        was wrong -- SHOWSEGS's own already-verified-exact code settles
        it (finding 121).

        Reads BLK's interface text two blocks (1024 bytes) at a time via
        `BLOCKREAD`, scanning each chunk byte by byte: a `CHR(16)` skips
        two bytes outright, a letter starts a run handed to `IDSEARCH` --
        the compiler's own reserved-word lookup (finding 109), reused
        here purely to advance past one identifier -- and a bare `CHR(13)`
        immediately followed by `CHR(0)` marks the interface's own true
        end. Whichever of those two ways the scan stops, NAMESTART holds
        the width to print the whole 1024-byte chunk trimmed to (UCSD's
        own `WRITE(packed-array:N)` idiom, printing exactly N characters
        from the start); the outer `REPEAT` then reads another two
        blocks (BLK advanced by 2 each time) until DONE.

        IDSEARCH's own `VAR IDREC` is not the 1- or 2-word cursor it
        looks like from PASCALCO.text's own call
        (`IDSEARCH(SYMCURSOR,SYMBUFP^)`) -- the gap between where this
        procedure's own code last touches it (SY, at IDREC's second word)
        and where NAMESTART sits next in the frame is five more words,
        exactly filling out a 7-word structure once declared: `IDCURSOR`
        below, unread past its first two fields the same way `REFENTRY`'s
        own SPARE is (finding 111). That 7-word figure is what actually
        closes this procedure's frame size exactly, not a guess kept
        around for looking plausible: `521` declared words (`IDCURSOR`'s
        7 + `NAMESTART`'s 1 + `DONE`'s 1 + `RBUF`'s 512) is exactly half
        of Apple's own `data=1042`, the same words-to-bytes-in-the-field
        relationship already established for every other procedure in
        this file (`CHECKERR`'s 42-word copy at `data=84`, `COPYLINK`'s
        267 words at `data=534`).

        `SY = 52`'s own meaning (some reserved word that ends the scan
        early) and the exact identifier-character test are reconstructed
        from the shape of the binary, not checked instruction for
        instruction past that (finding 121). }
      FUNCTION SHOWINFO(BLK: INTEGER): BOOLEAN;
        TYPE
          IDCURSOR = RECORD
                       IDX, SY: INTEGER;
                       SPARE: ARRAY [1..5] OF INTEGER
                     END;
        VAR
          ID: IDCURSOR;
          NAMESTART: INTEGER;
          DONE: BOOLEAN;
          RBUF: PACKED ARRAY [0..1023] OF CHAR;
      BEGIN
        SHOWINFO := TRUE;
        IF BLK <= 0 THEN
        BEGIN
          SHOWINFO := FALSE;
          EXIT(SHOWINFO)
        END;
        DONE := FALSE;
        REPEAT
          IF BLOCKREAD(INFILE, RBUF, 2, BLK - 1) <> 2 THEN
          BEGIN
            WRITE('Interface read error');
            WRITELN;
            SHOWINFO := FALSE;
            DONE := TRUE
          END
          ELSE
          BEGIN
            BLK := BLK + 2;
            ID.IDX := 0;
            REPEAT
              IF RBUF[ID.IDX] = CHR(16) THEN
              BEGIN
                ID.IDX := ID.IDX + 2
              END;
              IF RBUF[ID.IDX] IN ['A'..'Z', 'a'..'z'] THEN
              BEGIN
                NAMESTART := ID.IDX;
                IDSEARCH(ID, RBUF);
                IF ID.SY = 52 THEN
                BEGIN
                  DONE := TRUE
                END
              END;
              IF RBUF[ID.IDX] = CHR(13) THEN
              BEGIN
                IF RBUF[ID.IDX + 1] = CHR(0) THEN
                BEGIN
                  NAMESTART := ID.IDX;
                  ID.IDX := 1023
                END
              END;
              ID.IDX := ID.IDX + 1
            UNTIL DONE OR (ID.IDX > 1023);
            WRITE(OUTFILE, RBUF:NAMESTART);
            WRITELN(OUTFILE)
          END
        UNTIL DONE;
        WRITELN(OUTFILE)
      END;

      { Fetch the next reference-stream entry into W, refilling RBUF one
        disk block at a time. BYTEPOS/RBLOCK/RBUF are SHOWONE's own
        locals, read and written here directly by nested-procedure
        scoping rather than passed as parameters. `MOVELEFT` copies the
        *whole* 16-byte entry in one call -- untyped `VAR` parameters, so
        no `@` appears anywhere in this procedure: Apple's own compiler
        rejects it outright (error 400), unlike the fast tier, which
        accepted it without complaint and so never caught this until the
        acceptance-tier recompile this session (finding 111 update,
        2026-08-27). `BLOCKREAD` is the standard Pascal function this
        actually is at the source level (language reference, "Untyped
        File I/O Operations") -- a hand-declared `FUNCTION FBLOCKIO(...);
        FORWARD;` (segment 0 procedure 28), the `GLOBALS.TEXT` idiom
        SYSTEM.PASCAL's own source uses to reach segment 0 directly, was
        tried first and does not work here even with `(*$U-*)` (see the
        file header comment); `BLOCKREAD` compiles to the identical
        `CXP 0,28` without any of that, which is what the fast tier's
        own "guessing you meant blockread instead" was pointing at. What
        wasn't nailed down before this session was that GETWORD's own
        read position is entry-indexed (IXA 8, an 8-word/16-byte stride)
        counting BYTEPOS down from 32 to 0 across one 512-byte block
        (32 * 16 = 512), computed inline rather than stored in a local
        of its own -- an `IDX` local here matched the binary's own
        control flow but not its frame size (`params=2/data=4`, two
        words over Apple's `data=2`); removing it and folding
        `32 - BYTEPOS` directly into the `MOVELEFT` call closed the gap
        exactly. Verified instruction for instruction against the
        binary and acceptance-tier compiled: `params=2/data=2`, matching
        Apple's own SYSTEM.COMPILER output exactly (LIBMAP session,
        2026-08-27), including the read-error path (a failed read
        forces RKIND to 0 so SHOWONE's own UNTIL sees end-of-stream
        rather than looping on garbage). }
      PROCEDURE GETWORD(VAR W: REFENTRY);
        VAR
          ERR: BOOLEAN;
      BEGIN
        ERR := FALSE;
        IF BYTEPOS = 0 THEN
        BEGIN
          BYTEPOS := 32;
          IF BLOCKREAD(INFILE, RBUF, 1, RBLOCK) <> 1 THEN
          BEGIN
            WRITE(OUTFILE, 'library read error!');
            WRITELN(OUTFILE);
            ERR := TRUE
          END
          ELSE
          BEGIN
            RBLOCK := RBLOCK + 1
          END
        END;
        MOVELEFT(RBUF[32 - BYTEPOS], W, 16);
        IF ERR THEN
        BEGIN
          W.RKIND := 0
        END;
        BYTEPOS := BYTEPOS - 1
      END;

      { Print one cross-reference note: the label the caller passes
        (' global'/' public'/' constant'/' separate'/' unit'/' private'),
        "word/byte/big reference" (from ENTRY.RVAL1, a three-way case),
        then "(N times)" or "(once)" (from ENTRY.RVAL2), then read and
        discard (RVAL2+7) DIV 8 more raw entries -- ENTRY is SHOWONE's own
        local, read here by the same nested-procedure scoping GETWORD
        already uses, not passed in. The old guess here -- `VAR NAME:
        STRING`, reasoning that every call site passes a string constant's
        own address -- does not survive Apple's own compiler: error 154,
        actual parameter must be a variable, on exactly that (a `VAR`
        parameter cannot bind to a literal). A plain value `STRING`
        parameter is passed by address anyway (strings are variable-size,
        so UCSD copies via a hidden reference even for a value param),
        which is almost certainly what produced the original mistaken
        reading. (finding 111 update, 2026-08-27) Compiles to
        `params=2/data=102` against Apple's `2/104` -- one word short,
        same small documented-not-forced gap as this file's own
        `NEEDSSWAP`/`SWAPALL` (finding 120). }
      PROCEDURE SHOWREF(NAME: STRING);
        VAR
          I, LAST: INTEGER;
          DUMMY: REFENTRY;
      BEGIN
        IF LISTREFS THEN
        BEGIN
          WRITE(OUTFILE, NAME:12);
          CASE ENTRY.RVAL1 OF
            0: WRITE(OUTFILE, ' word reference');
            1: WRITE(OUTFILE, ' byte reference');
            2: WRITE(OUTFILE, ' big reference')
          END;
          IF ENTRY.RVAL2 <> 1 THEN
          BEGIN
            WRITE(OUTFILE, ' (');
            WRITE(OUTFILE, ENTRY.RVAL2);
            WRITE(OUTFILE, ' times)')
          END
          ELSE
          BEGIN
            WRITE(OUTFILE, ' (once)')
          END;
          WRITELN(OUTFILE)
        END;
        I := 1;
        LAST := (ENTRY.RVAL2 + 7) DIV 8;
        WHILE I <= LAST DO
        BEGIN
          GETWORD(DUMMY);
          I := I + 1
        END
      END;

    BEGIN
      WRITE(OUTFILE, SEGDICT.SEGNAME[SEGNUM]:8);
      CASE SEGDICT.SEGKIND[SEGNUM] OF
        0: BEGIN
             WRITE(OUTFILE, '  completely linked segment');
             WRITELN(OUTFILE);
             IF SEGDICT.TEXTADR[SEGNUM] <> 0 THEN
             BEGIN
               NEEDINFO := NOT SHOWINFO(SEGDICT.TEXTADR[SEGNUM])
             END;
             EXIT(SHOWONE)
           END;
        1: BEGIN
             WRITE(OUTFILE, '  Pascal host outer block');
             WRITELN(OUTFILE)
           END;
        2: BEGIN
             WRITE(OUTFILE, '  Pascal segment');
             WRITELN(OUTFILE);
             NEEDINFO := NOT SHOWINFO(SEGDICT.TEXTADR[SEGNUM])
           END;
        3, 5, 6: BEGIN
             WRITE(OUTFILE, '  library unit');
             IF SEGDICT.SEGKIND[SEGNUM] = 5 THEN
             BEGIN
               WRITE(OUTFILE, ' (UNLINKED INTRINSIC)');
               WRITELN(OUTFILE)
             END
             ELSE IF SEGDICT.SEGKIND[SEGNUM] = 6 THEN
             BEGIN
               WRITE(OUTFILE, ' (LINKED INTRINSIC)');
               WRITELN(OUTFILE)
             END
             ELSE
             BEGIN
               WRITELN(OUTFILE)
             END;
             NEEDINFO := NOT SHOWINFO(SEGDICT.TEXTADR[SEGNUM])
           END;
        4: BEGIN
             WRITE(OUTFILE, '  separate procedure segment');
             WRITELN(OUTFILE)
           END;
        7: BEGIN
             WRITE(OUTFILE, '  data segment');
             WRITELN(OUTFILE);
             EXIT(SHOWONE)
           END
      END;
      BYTEPOS := 0;
      RBLOCK := SEGDICT.ADDRLEN[SEGNUM].ADDR +
                  (SEGDICT.ADDRLEN[SEGNUM].LENG + 511) DIV 512;
      IF NOT (LISTLINK OR NEEDINFO) THEN EXIT(SHOWONE);
      REPEAT
        GETWORD(ENTRY);
        IF SWAPPED THEN
        BEGIN
          MOVELEFT(ENTRY, SWAPBUF, 16);
          I := 4;
          LAST := 7;
          WHILE I <= LAST DO
          BEGIN
            SWAPBYTES(SWAPBUF[I]);
            I := I + 1
          END;
          MOVELEFT(SWAPBUF, ENTRY, 16)
        END;
        IF ENTRY.RKIND <> 0 THEN
        BEGIN
          IF VALIDNAME(ENTRY.RNAME) THEN
          BEGIN
            CASE ENTRY.RKIND OF
              6: BEGIN
                   IF LISTLINK THEN
                   BEGIN
                     WRITE(OUTFILE, ENTRY.RNAME:12);
                     WRITE(OUTFILE, ' global addr    P #');
                     WRITE(OUTFILE, ENTRY.RVAL1);
                     WRITE(OUTFILE, ',  I #');
                     WRITE(OUTFILE, ENTRY.RVAL2);
                     WRITELN(OUTFILE)
                   END
                 END;
              7: BEGIN
                   IF LISTLINK THEN
                   BEGIN
                     WRITE(OUTFILE, ENTRY.RNAME:12);
                     WRITE(OUTFILE, ' public var  base = ');
                     WRITE(OUTFILE, ENTRY.RVAL1);
                     WRITELN(OUTFILE)
                   END
                 END;
              8: BEGIN
                   IF LISTLINK THEN
                   BEGIN
                     WRITE(OUTFILE, ENTRY.RNAME:12);
                     WRITE(OUTFILE, ' constant value of ');
                     WRITE(OUTFILE, ENTRY.RVAL1);
                     WRITELN(OUTFILE)
                   END
                 END;
              9, 10: BEGIN
                   IF LISTREFS THEN
                   BEGIN
                     WRITE(OUTFILE, ENTRY.RNAME:12);
                     WRITE(OUTFILE, ' external proc  P #');
                     WRITE(OUTFILE, ENTRY.RVAL1);
                     WRITELN(OUTFILE)
                   END
                 END;
              11, 12: BEGIN
                   WRITE(OUTFILE, ENTRY.RNAME:12);
                   WRITE(OUTFILE, ' separate proc  P #');
                   WRITE(OUTFILE, ENTRY.RVAL1);
                   WRITELN(OUTFILE)
                 END;
              2: SHOWREF(' global');
              3: SHOWREF(' public');
              5: SHOWREF(' constant');
              13, 14: SHOWREF(' separate');
              1: SHOWREF(' unit');
              4: SHOWREF(' private');
              0: BEGIN
                   IF SEGDICT.SEGKIND[SEGNUM] = 5 THEN
                   BEGIN
                     WRITE(OUTFILE, ' Private dataseg # = ');
                     WRITE(OUTFILE, ENTRY.RVAL2);
                     WRITELN(OUTFILE)
                   END
                 END
            END
          END
        END
      UNTIL ENTRY.RKIND = 0
    END;

  BEGIN
    SEGNUM := 0;
    LASTSEG := 15;
    WHILE SEGNUM <= LASTSEG DO
    BEGIN
      WITH SEGDICT.ADDRLEN[SEGNUM] DO
      IF (LENG > 0) OR (ADDR > 0) THEN
      BEGIN
        IF SEGDICT.SEGINFO[SEGNUM].SEGNUM <> 0 THEN
        BEGIN
          WRITE(OUTFILE, 'Segment #');
          WRITE(OUTFILE, SEGDICT.SEGINFO[SEGNUM].SEGNUM:2);
          WRITE(OUTFILE, ':  ');
          WRITELN(OUTFILE)
        END
        ELSE
        BEGIN
          WRITE(OUTFILE, 'Segment #');
          WRITE(OUTFILE, SEGNUM);
          WRITE(OUTFILE, ':  ');
          WRITELN(OUTFILE)
        END;
        IF SEGDICT.SEGINFO[SEGNUM].VERSION <> 0 THEN
        BEGIN
          WRITE(OUTFILE, 'System version = ');
          WRITE(OUTFILE, VERSTRS[SEGDICT.SEGINFO[SEGNUM].VERSION]);
          WRITE(OUTFILE, ', code type is ');
          WRITE(OUTFILE, TYPESTRS[SEGDICT.SEGINFO[SEGNUM].MTYPE]);
          WRITELN(OUTFILE)
        END
        ELSE
        BEGIN
          WRITE(OUTFILE, 'Pre-II.1 segment');
          WRITELN(OUTFILE)
        END;
        SHOWONE(SEGNUM);
        WRITELN(OUTFILE);
        WRITE(OUTFILE, '----------------------------------------':75);
        WRITELN(OUTFILE);
        WRITELN(OUTFILE)
      END;
      SEGNUM := SEGNUM + 1
    END
  END;

  { Prompt for a library, validate its dictionary, and print its map --
    then loop and do it again. An empty library name is the only way out
    (`EXIT(PROGRAM)`), matching the disassembly's own backward branch to
    this procedure's very top on both the "bad file" and "not a code
    file" paths: the whole body is one `REPEAT`.

    LISTMAP, set once by the outer block before its own first call and
    cleared right after, gates the map-output-filename prompt below --
    true only for the very first library in a run, so every later one
    appends to the SAME already-open OUTFILE instead of re-prompting.

    Prompts and the "bad file"/"not a code file" messages go to the
    plain, unnamed console (bare WRITE/WRITELN/READ/READLN, matching the
    disassembly's own addressing for Pascal's predeclared INPUT/OUTPUT,
    distinct from `LOD` on a real global) -- OUTFILE, the user-chosen map
    destination, is only ever touched by name once it is open.

    Both '.CODE' and '.TEXT' get appended with `INSERT(lit, NAME,
    LENGTH(NAME)+1)`, not `CONCAT` -- the disassembly's own call is
    `SINSERT`, and using `CONCAT` here (as `BINDER.text`'s own retry-
    suffix logic does successfully elsewhere) cost a real, avoidable
    41-word hidden result temp: `X := CONCAT(X, lit)` and `INSERT(lit, X,
    LENGTH(X)+1)` are not the same instruction sequence even though they
    have the same effect, and only one of them is what this procedure's
    own binary actually does (finding 120). Declaring MAPNAME before
    LIBNAME (reversed from a first guess) and reusing TEMP1/TEMP2 for the
    validation loop's own counters, rather than fresh locals, closed the
    rest of the gap: `params=0/data=170` against Apple's `0/172`, one
    word short, documented rather than forced. The '.TEXT'-suffix
    CONSOLE:-default logic is otherwise reconstructed from the shape of
    the binary and not yet checked instruction for instruction -- the
    disassembly's own version also scans the name character by character
    for something this rewrite doesn't reproduce, and it is not yet
    understood what for; it did not cost the word this session closed. }
  PROCEDURE MAPLIBRARY;
    VAR
      C: CHAR;
      OK: BOOLEAN;
      MAPNAME: STRING[80];
      LIBNAME: STRING[80];
  BEGIN
    REPEAT
      SWAPPED := FALSE;
      CLOSE(INFILE);
      WRITE('enter library name: ');
      READ(LIBNAME);
      READLN;
      IF LIBNAME = '' THEN
      BEGIN
        CLOSE(OUTFILE, LOCK);
        EXIT(PROGRAM)
      END;
      IF LIBNAME = '*' THEN
      BEGIN
        LIBNAME := '*SYSTEM.LIBRARY'
      END;
      RESET(INFILE, LIBNAME);
      IF IORESULT <> 0 THEN
      BEGIN
        INSERT('.CODE', LIBNAME, LENGTH(LIBNAME) + 1);
        RESET(INFILE, LIBNAME)
      END;
      IF BLOCKREAD(INFILE, SEGDICT, 1, 0) <> 1 THEN
      BEGIN
        WRITE('bad file');
        WRITELN;
        OK := FALSE
      END
      ELSE
      BEGIN
        IF NEEDSSWAP(SEGDICT.ADDRLEN) THEN
        BEGIN
          SWAPALL(SEGDICT);
          SWAPPED := TRUE
        END;
        TEMP2 := 0;
        TEMP1 := 15;
        OK := TRUE;
        WHILE (TEMP2 <= TEMP1) AND OK DO
        BEGIN
          WITH SEGDICT.ADDRLEN[TEMP2] DO
          IF (LENG <= 0) OR (ADDR <= 0) OR (ADDR > 300) OR
             NOT VALIDNAME(SEGDICT.SEGNAME[TEMP2]) THEN
          BEGIN
            WRITE('not a code file');
            WRITELN;
            OK := FALSE
          END;
          TEMP2 := TEMP2 + 1
        END
      END
    UNTIL OK;
    WRITE('list linker info table (Y/N)? ');
    REPEAT
      READ(C)
    UNTIL C IN ['Y', 'y', 'N', 'n'];
    WRITE(C);
    WRITELN;
    LISTLINK := C IN ['Y', 'y'];
    IF LISTLINK THEN
    BEGIN
      WRITE('list referenced items (Y/N)? ');
      REPEAT
        READ(C)
      UNTIL C IN ['Y', 'y', 'N', 'n'];
      WRITE(C);
      WRITELN;
      LISTREFS := C IN ['Y', 'y']
    END
    ELSE
    BEGIN
      LISTREFS := FALSE
    END;
    IF LISTMAP THEN
    BEGIN
      REPEAT
        WRITE('map output file name: ');
        READ(MAPNAME);
        READLN;
        IF MAPNAME = '' THEN
        BEGIN
          MAPNAME := 'CONSOLE:'
        END;
        IF POS('.TEXT', MAPNAME) <> LENGTH(MAPNAME) - 4 THEN
        BEGIN
          INSERT('.TEXT', MAPNAME, LENGTH(MAPNAME) + 1)
        END;
        REWRITE(OUTFILE, MAPNAME);
        OK := IORESULT = 0
      UNTIL OK
    END;
    WRITELN(OUTFILE);
    WRITE(OUTFILE, '  LIBRARY MAP FOR ');
    WRITE(OUTFILE, LIBNAME);
    WRITELN(OUTFILE);
    WRITELN(OUTFILE);
    IF LENGTH(SEGDICT.COMMENT) > 0 THEN
    BEGIN
      WRITE(OUTFILE, ' ':5);
      WRITE(OUTFILE, SEGDICT.COMMENT);
      WRITELN(OUTFILE);
      WRITELN(OUTFILE)
    END;
    WRITELN(OUTFILE)
  END;

{ TEMP2/TEMP1 are the VERSTRS-init loop's own counters -- the outer
  program block has no locals of its own beyond the global frame, and the
  binary reuses these two named globals for exactly this one loop rather
  than anything a name like TEMP1/TEMP2 would suggest elsewhere. Then an
  unconditional REPEAT MAPLIBRARY; LISTMAP:=FALSE; SHOWSEGS UNTIL FALSE --
  the binary's own loop-back condition is a literal constant, matching
  MAPLIBRARY's `EXIT(PROGRAM)` on an empty name as the only way out.
  FINIT for OUTFILE/INFILE and the FCLOSE pair at exit are both automatic
  (finding 91's rule, confirmed again here) -- no explicit call for
  either appears in this block. }
BEGIN
  WRITE('Apple Library Map Utility [1.3]');
  WRITELN;
  TEMP2 := 0;
  TEMP1 := 7;
  WHILE TEMP2 <= TEMP1 DO
  BEGIN
    VERSTRS[TEMP2] := 'unknown';
    TEMP2 := TEMP2 + 1
  END;
  VERSTRS[1] := 'A2/1.0';
  VERSTRS[2] := 'A2/1.1';
  VERSTRS[5] := 'A2/1.2';
  VERSTRS[6] := 'A2/1.3';
  TYPESTRS[0] := 'Undefined';
  TYPESTRS[1] := 'P-Code (most sig. 1st)';
  TYPESTRS[2] := 'P-Code (least sig. 1st)';
  TYPESTRS[3] := 'PDP-11';
  TYPESTRS[4] := '8080';
  TYPESTRS[5] := 'Z-80';
  TYPESTRS[6] := 'GA 440';
  TYPESTRS[7] := '6502';
  TYPESTRS[8] := '6800';
  TYPESTRS[9] := 'TI 9900';
  LISTMAP := TRUE;
  REPEAT
    MAPLIBRARY;
    LISTMAP := FALSE;
    SHOWSEGS
  UNTIL FALSE
END.
