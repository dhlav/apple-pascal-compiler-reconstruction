# The Apple Pascal 1.3 disk set

What every file is for, and how much of it has been reconstructed. The
descriptions in the first section are the user's, kept verbatim. The status
column and the second section are this repo's.

The machine-readable companion is `analysis/diskset-inventory.txt`,
regenerated by `tools/diskmap.py` on every build: every file on the three
1.3 evidence disks with its per-segment breakdown -- dictionary slot, segment
number, SEGINFO version, mtype, size, and how many procedures are p-code and
how many are native 6502. That file is generated and this one is not; where
they disagree, the generated one is right.

**The target is 1.3 and the 128K system only** (`128K.APPLE` +
`128K.PASCAL`). The 64K `SYSTEM.APPLE`/`SYSTEM.PASCAL` and all of 1.1 are
archived -- see **Archived** at the end. The core rows below name the 128K
files; the descriptions are still the user's, verbatim.

## The disks, rebuilt

**359,323 of 430,080 bytes** across the three disks (findings 289, 290):
`tools/mkdiskset.py` writes each volume from the rebuilt files, the text
sources, the rebuilt boot and Apple's directory entries, and
`analysis/diskset-account.txt` accounts for every byte by region.
`probe_diskset.py` requires the regions to balance against a direct image
compare and each to differ by exactly what its finding says. In scope,
without the archived 64K pair, it is 351,873 of 374,784. Nineteen files are
identical in place; `SYSTEM.LIBRARY` is the largest gap in place (16,234,
two blocks short, 287), an accepted exception: its text blocks came from a
compiler other than the shipped one (286c, 290), and slot by slot it is
16,417 of 19,456, then `SETUP.CODE` (3,943, 273).

## Core System Files

| file | what it is | status |
|---|---|---|
| 128K.APPLE | Boot files that configure the Apple hardware. | **reconstructed -- all 16,384 bytes identical to shipped** (finding 279): the 128K interpreter as three `.ABSOLUTE` assemblies (`src/native/interp/`, generated by `tools/absdis.py` from `128K.hints`), assembled by `SYSTEM.ASSMBLER` and joined by `MAKEINTP` on the 1.3 system. The byte compare cannot check the code/data split: an absolute assembly has no relocation (`probe_128k_apple.py`) |
| 128K.PASCAL | The main operating system and command menu. | **22469 of 23040 bytes: the whole file but three slack tails that were another tool's memory** (finding 284): Apple's compiler on `PASCALSYSTEM.text`, finished by `MAKEOS` on the 1.3 system, which splits segment 0 as the 128K boot loads it (283). `probe_128k_pascal.py`. The route there, procedure by procedure, is findings 136-284 |
| SYSTEM.MISCINFO | Screen and keyboard setup data for your terminal. | **every setting and the zero tail by Apple's SETUP, 365 of 512 bytes** (finding 277): a 53-field recipe typed into the shipped `SETUP.CODE`. The other 147 are memory SETUP never writes; Apple's was `SYSTEM.FILER`'s code, which a 128K run does not leave there (`probe_miscinfo.py`) |

## Main Utilities

| file | what it is | status |
|---|---|---|
| SYSTEM.EDITOR | The text editor used to write code. | **reconstructed -- the whole file, all 25,600 bytes identical to shipped** (finding 272): compiled by Apple's compiler, segments 1 and 7-12 copied into slots 1-7 by Apple's `LIBRARY.CODE`. 129 of 129 procedures in seven segments, the second compile, from UCSD's II.0 screen editor (`evidence/reference/ucsd-ii0-editor`) and the binary |
| SYSTEM.FILER | The file manager used to copy, list, and delete files. | **reconstructed -- the whole file, all 15,360 bytes identical to shipped** (finding 271): compiled by Apple's compiler, slot 1 copied by Apple's `LIBRARY.CODE`. 56 of 56 procedures, one segment, first compile, from UCSD's II.0 Filer (`evidence/reference/ucsd-ii0-filer`) and the binary, inside the 1.3 operating system's own declarations |
| SYSTEM.COMPILER | Translates your Pascal code into machine-readable code. | **reconstructed -- the whole file, all 39,936 bytes identical to shipped** (finding 267e): compiled by Apple's compiler, `SEARCH` assembled and linked by Apple's assembler and Linker, then copied into a fresh codefile by Apple's `LIBRARY.CODE`, which is what leaves slot 0 blank (finding 105a, closed). 147 of 147 procedures (finding 90), all 15 segments. |
| SYSTEM.LINKER | Combines different compiled code pieces into one program. | **reconstructed -- the whole file, all 12,800 bytes identical to shipped** (finding 268): compiled by Apple's compiler, slot 1 copied by Apple's `LIBRARY.CODE`. 51 of 51 procedures, one segment, from UCSD's I.5 linker (Roger Sumner, 1978) and the binary; Apple's additions -- byte sex, intrinsic units, data segments, disk-direct copying -- carry placeholder names |
| SYSTEM.ASSMBLER | Low-level assembly language translator. | **the whole file, 25,600 bytes, reproduced by Apple's own compiler and Librarian** (finding 267f) with `PASCALIO` -- which nothing on the disks rebuilds -- copied from the shipped file; **every procedure in all six segments is byte-exact, 90 of 95** (findings 237-266): `TLA` 38, `ASSEMBLE` 33, `PROCEND` 9, `INITIALI` 6, `SYMTBLDU` 3, `PRINTERR` 1, each produced by Apple's own compiler from this source, and the file's names come from UCSD's own I.5 Adaptable Assembler wherever the bytes confirm the role (finding 263) -- `TLA` is The Waterloo Last Assembler. The five that differ are `PASCALIO`'s. `TLA` is a SEGMENT PROCEDURE under `(*$U-*)` on segment 1, the five nested ones on 7-11, the global area balances at 2217 words. The `PASCALIO` segment cannot be rebuilt from anything on the 1.3 disks (finding 235b). Also the acceptance tier for `src/native/` (finding 44e) |

## Configuration and Setup

| file | what it is | status |
|---|---|---|
| SETUP.CODE | Changes hardware settings like your screen size. | **all 54 procedures instruction- and frame-identical** (finding 273), from UCSD's SETUP D1 (`evidence/reference/ucsd-ii0-setup`) with Apple's six S.2 edits. Not the whole file, and no 1.3 source can make it so: the shipped file predates the SEGINFO version word (0 in every slot) and its compiler left stale bytes in 34 alignment pads the 1.3 compiler writes as 0. ## Also on the disks

The list above is the interesting half. The disks carry more:

* **`LINEFEED.CODE`** (APPLE3) -- suppresses line feeds. One procedure, 38
  bytes, and **reconstructed** (finding 99a): kept whole from Apple's 1.3
  compiler, every byte to the end of the code but the version field,
  `probe_v2_binaries.py` (288c).
* **`SYSTEM.CHARSET`** (APPLE1) -- the hi-res character set, 1024 bytes.
  **Reconstructed**, identical, written by `MAKECHRS` from
  `src/data/CHARSET.TEXT` on the 1.3 system (finding 278).
* **`SYSTEM.SYNTAX`** (APPLE1) -- the compiler's error messages.
  **Identical**, all 6144 bytes, from `src/text/SYSTEM.SYNTAX.text` and its
  `.layout`: the six lines with a DLE, and the editor's page zero (288).
* **`II40.MISCINFO`, `II80.MISCINFO`, `HAZEL.MISCINFO`** (APPLE3) -- the
  terminal profiles SETUP writes. Every setting and the zero tail
  reproduced by Apple's SETUP from recipes, 370, 396 and 361 of 512
  bytes; the rest is memory SETUP never writes (finding 277).
* **Nine `.TEXT` sample programs** (APPLE3) -- `BALANCED`, `CROSSREF`,
  `DISKIO`, `GRAFCHARS`, `GRAFDEMO`, `HILBERT`, `SPIRODEMO`, `TREE`,
  `HAZELGOTO`. **All identical**, every block, from `src/text/` and their
  `.layout`s: which lines Apple's editor gave a DLE, and each file's page
  zero with its margins and dates (finding 288, `probe_text_files.py`).
  (Their 1.1 `.CODE` twins, once the lifter's calibration corpus, are
  archived with 1.1.)

## What is left

Every difference still on the disks is named in `probe_diskset.py`, and
none can be closed with Apple's shipped tools:

* **Leftover memory in Apple's files**: slack past the last segment
  (`LIBMAP.CODE`, `FORMATTER.CODE`, `LINEFEED.CODE`, `128K.PASCAL`), the
  `.MISCINFO` bytes SETUP never writes, `6502.ERRORS`' first record fill,
  and the assembler's one uncleared byte in `FORMATTER.DATA` and the boot.
* **Version stamps**: `BINDER`, `SET40COLS` and `LINEFEED` are 1.1
  binaries (version 2 against 6). `SETUP.CODE` predates the version word
  and carries stale pads.
* **`SYSTEM.LIBRARY`**, the accepted exception (`docs/PLAN.md`).
* **Mastering residue**: dead directory space, and a removed `LINKER.INFO`
  with its block on `APPLE2`.

One segment is copied, not rebuilt: `PASCALIO` inside `SYSTEM.ASSMBLER`
(235b). The rest of the work is names -- placeholders for Apple's own
additions and unread operations. See `docs/PLAN.md`, *Carried forward*.

## Archived

Not targets, not read by the build, kept verbatim:

* **The 64K system** -- `SYSTEM.APPLE` and `SYSTEM.PASCAL` on the 1.3
  `APPLE1` image. They cannot leave that image without modifying evidence,
  so `disasm_utils.py`/`lift_utils.py` and `probe_split_segment.py` skip
  them by name. Their generated listings are in `archive/analysis/`.
* **Apple Pascal 1.1** -- the `APPLE2` image and the two UCSD 1.1 images,
  moved byte for byte to `evidence/archive/1.1/`; the 1.1 compiler source
  in `archive/src/pascal/1.1/`; every 1.1-only or 1.1-vs-1.3 tool and probe
  in `archive/tools/`; and the generated 1.1 analysis in
  `archive/analysis/`. See `archive/README.md`.
