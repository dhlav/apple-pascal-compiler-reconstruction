# The Apple Pascal 1.3 disk set

What every file is for, and how much of it has been reconstructed. The
descriptions in the first section are the user's, kept verbatim. The status
column and the second section are this repo's.

The machine-readable companion is `analysis/diskset-inventory.txt`,
regenerated by `tools/diskmap.py` on every build: every file on all six
evidence disks with its per-segment breakdown -- dictionary slot, segment
number, SEGINFO version, mtype, size, and how many procedures are p-code and
how many are native 6502. That file is generated and this one is not; where
they disagree, the generated one is right.

**The target is 1.3 and the 128K system** (`128K.APPLE` + `128K.PASCAL`).
The 64K `SYSTEM.PASCAL` and both 1.1 disks stay in `evidence/` and stay in
use: 1.1 ships source for utilities 1.3 ships only as codefiles, which is
how `LINEFEED` was reconstructed (finding 99a), and comparing the releases
is what says which files Apple actually rebuilt (finding 99c).

## Also on the disks

The list above is the interesting half. The disks carry more:

* **`128K.APPLE` and `128K.PASCAL`** (APPLE3) -- the 128K system, and the
  build target. Four of `128K.PASCAL`'s seven segments are byte-identical to
  `SYSTEM.PASCAL`'s: `USERPROG`, `FIOPRIMS`, `PRINTERR` and `FILEPROC`.
* **`LINEFEED.CODE`** (APPLE3) -- suppresses line feeds. One procedure, 38
  bytes, and **reconstructed** (finding 99a).
* **`SYSTEM.CHARSET`** (APPLE1) -- the hi-res character set, 1024 bytes.
* **`SYSTEM.SYNTAX`** (APPLE1) -- the compiler's error messages. Already a
  text file on the disk, so it is reproduced by writing the volume.
* **`II40.MISCINFO`, `II80.MISCINFO`, `HAZEL.MISCINFO`** (APPLE3) -- the
  terminal profiles SETUP writes.
* **Eleven `.TEXT` sample programs** (APPLE3) -- `BALANCED`, `CROSSREF`,
  `DISKIO`, `GRAFCHARS`, `GRAFDEMO`, `HILBERT`, `SPIRODEMO`, `TREE`,
  `HAZELGOTO`. Already source on the disk. The 1.1 APPLE3 disk ships the
  matching `.CODE` for each, which makes them a calibration corpus: Apple's
  source next to Apple's own output.

## What is left, by size

Counting procedures rather than bytes, and 1.3 only: 216 done of roughly
861. Every remaining target can be read before it is written: the sweep
covers the codefiles a 1.3 disk carries, plus the 1.1 copies of those same
files, and **it lifts 1147 of 1147 with the stack fully tracked**
(finding 100). The listings are in `analysis/utilities/`, p-code and
pseudo-Pascal side by side.

Files that ship only on a 1.1 disk -- `CALC.CODE` and the demo programs'
codefiles -- are out of *scope*, but they are still swept and still listed
in `analysis/utilities/`. Nothing is discarded: the demos' 1.1 `.CODE`
beside their `.TEXT` is the only source-and-output pair Apple left behind.
